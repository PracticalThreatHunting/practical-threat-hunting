Build: an original valid Sigma rule for the supplied DET-001 single-event behavior, using a UUID v4, correct current metadata, logsource, selections, modifiers/filters where justified, condition, false-positive notes, owner/status, references, and a reasoned ATT&CK mapping. 1. Change the principal in the maintenance filter to a different fictional role. Identify which positive and negative fixtures should change and which should remain unaffected. Treat the change as a contract proposal, not merely a YAML edit.
2. Add a processing-pipeline field mapping for a renamed device column. Demonstrate the generated target field and identify the native test needed to establish that the destination column has the expected meaning.
3. Evaluate whether DET-003 should have a Sigma correlation representation in your selected backend. Record support for event-time ordering, pair multiplicity, equal-time handling, duplicate identity, and late-arrival rereads separately. A documented unsupported result is an acceptable answer; an unexplained conversion success is not.

The answer checks actual converter output against the contract and refuses to call a generated predicate a complete scheduled detection.
