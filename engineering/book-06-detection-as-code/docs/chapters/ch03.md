# Chapter 3: Telemetry Is an API

This is a cumulative study checkpoint in the edition, not a separate historical release.

## Artifact and proof scope

Case: correct logic fails because a normalized field disappears, timestamps use different zones, duplicate events arrive, and ingestion is delayed.

Build: logical event schema; raw-to-logical mappings; version-pinned normalization choice where useful; raw-event preservation; field types; null-versus-missing policy; source and ingest timestamps; identity/entity keys; deduplication assumptions; completeness/freshness SLOs; compatibility and mapping-version policy; data-quality assertions.

Prove: contract and round-trip fidelity tests using malformed, duplicated, delayed, and schema-shifted fixtures. Explain that CIM, ASIM, ECS, and OCSF are choices with losses and versions, not magic universal schemas.

## Exercises and answer criteria

1. Add a timestamp represented as Boolean `true` and confirm that the normalizer rejects it. Explain why a broad numeric type check could accept it accidentally.
2. Design an adapter for a source that supplies a local timestamp and an explicit numeric offset. Specify the preserved raw value, UTC conversion, malformed-offset behavior, and two boundary fixtures. Do not assume the analyst's local time zone.
3. Propose a schema migration that replaces a reusable username with an immutable account identifier. Identify the affected deduplication, correlation, output, enrichment, and historical-test assumptions. Define the evidence needed before both old and new records can be evaluated together.

The answer preserves raw provenance, rejects explicit null where required, explains duplicate conflicts, and keeps event time separate from ingestion.
