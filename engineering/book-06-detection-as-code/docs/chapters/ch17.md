# Chapter 17: Package Once, Configure by Environment

This is a cumulative study checkpoint in the edition, not a separate historical release.

## Artifact and proof scope

Case: development, staging, and production contain hand-edited variants with no reliable relationship.

Build: immutable versioned release bundle containing contract, Sigma/native implementations, tests, evidence, alert/runbook metadata, manifest, checksums, dependency declarations, and environment overlays for IDs, workspaces/indexes, schedules, thresholds, and destination-specific settings. Separate logic, configuration, and secrets. Provide dry-run adapters for the reference Microsoft and Splunk targets.

Prove: reproducible bundle hashes; configuration schema; no embedded secrets; dry-run plan; environment diff limited to approved keys; current packaging path documentation.

## Exercises and answer criteria

1. Add an unapproved threshold override to a copy of the development overlay. Describe which behavioral tests must change and why an environment-only review must reject it.
2. Build twice, compare digests, then change one native-query comment and rebuild. Explain why both a semantic review and a byte identity remain useful.
3. Simulate a console edit by modifying an observed-state file. Write the evidence needed to reconcile it without losing an emergency repair or accepting an undocumented exclusion.

The answer preserves one content digest, classifies behavioral configuration, excludes secrets, and makes a disabled plan reviewable.
