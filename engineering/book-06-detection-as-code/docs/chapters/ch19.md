# Chapter 19: Observe the Detection Itself

This is a cumulative study checkpoint in the edition, not a separate historical release.

## Artifact and proof scope

Case: a dashboard calls a rule healthy even though its source has stopped sending data.

Build: detection-health events and monitors for source freshness/volume, schema drift, parser/mapping errors, query/scheduler failure, execution duration, result/alert materialization, enrichment health, zero-result anomalies, volume drift, and synthetic canary events; owner-routed dashboard; SLO and error-budget policy.

Prove: inject failures and show they route to the correct owner. Emphasize that zero alerts is neither proof of health nor proof of safety.

## Exercises and answer criteria

1. Design a health record for an event that arrives after the accepted lookback. Distinguish source availability from timeliness.
2. Explain why a global source-volume monitor can miss a single-tenant outage. Choose a partition and state its cost.
3. Inject stale enrichment using the supplied DET-004 cases. Confirm that the result contains a health route and does not claim a complete correlation.

The answer distinguishes source, mapping, scheduler, materialization, and consumer health, with an appropriate owner for each injected failure.
