## Artifact and proof scope

Build: a production KQL implementation for an explicitly named runtime and rule type; parameter handling; early filters; schema-safe projection; event/ingestion-time logic; only necessary joins/aggregation; deduplication; entity projection; custom details/evidence; alert payload; schedule/lookback; rule resource/IaC; comments linked to the contract.

Prove: query execution on the pinned Kusto/native test target; expected matches/nonmatches; missing-column behavior; late arrival; overlap/idempotency; target rule-resource validation; output-field inspection; measured execution profile. Distinguish query correctness from Sentinel rule-resource behavior.

1. Change only the query period to five minutes while retaining the thirty-minute contract. Identify a late-event case that the resource could exclude and explain why a query-only test would miss the defect.
2. Replace the principal output column with a renamed field. List every resource and consumer reference that must change and define the native materialization check that proves the mapping still works.
3. Design a native overlap test that distinguishes duplicate candidate rows from duplicate consumer tasks. Record the stable signal key, scheduler runs, target output, and consumer ledger separately.

The answer distinguishes native query output from Sentinel resource scheduling and alert materialization, with separate evidence for each.
