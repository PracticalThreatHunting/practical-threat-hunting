# Chapter 20: Turn Analyst Outcomes into Evidence

This is a cumulative study checkpoint in the edition, not a separate historical release.

## Artifact and proof scope

Case: thousands of analyst dispositions labeled false positive contain no diagnosis useful to engineering.

Build: disposition taxonomy; reason codes; minimum evidence fields; label-confidence and sampling policy; quality review; feedback-to-ticket automation; change-proposal template; tests that distinguish logic error, expected benign match, duplicate, bad data, bad enrichment, and poor alert presentation.

Prove: transform a synthetic batch of inconsistent dispositions into reviewed engineering signals and reject low-evidence feedback. Cover the producer/consumer interface only; do not teach triage or incident handling.

## Exercises and answer criteria

1. Classify a correct match to an approved administrative action. Explain why benign outcome alone does not prove a predicate defect.
2. Supply two alerts with the same principal but different event-pair keys. Decide what evidence is required before calling them duplicates.
3. Rewrite a low-evidence false-positive report into a request for the minimum missing information. Do not invent an outcome to make the record complete.

The answer retains outcome and engineering diagnosis separately and refuses an automatic change from unsupported feedback.
