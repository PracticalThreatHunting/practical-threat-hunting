# Chapter 15: Enrichment and Correlation Are Dependencies

This is a cumulative study checkpoint in the edition, not a separate historical release.

## Artifact and proof scope

Case: a stale identity or asset lookup silently changes entity resolution, severity, or match behavior.

Build: versioned enrichment interface; provenance; freshness/TTL; key/cardinality expectations; entity-resolution rules; missing/stale/ambiguous behavior; correlation key and window semantics; degraded-mode output; dependency health check; failure injection.

Prove: fresh, stale, missing, duplicated, and conflicting enrichment cases; defined degraded output; observable dependency failure. Do not turn this into threat-intelligence sourcing or investigation.

## Exercises and answer criteria

1. Change a mapping's `valid_to` to equal the event time. Predict the degraded state and confirm the exclusive upper boundary.
2. Duplicate a mapping row and explain why the reference treats it as ambiguity even when both rows contain the same canonical principal.
3. Design an operational refresh and rollback policy for the SPL resolution adapter. Include snapshot identity, one-row-per-event enforcement, freshness, partial-source failure, and a consumer-safe degraded mode.

The answer uses event-time validity and evaluation-time freshness independently, rejects ambiguous resolution, and preserves degraded output.
