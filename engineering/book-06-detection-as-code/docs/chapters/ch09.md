# Chapter 9: Turn Observable Behavior into Test Cases

This is a cumulative study checkpoint in the edition, not a separate historical release.

## Artifact and proof scope

Case: the single happy-path example passes while obvious benign, boundary, and dirty cases behave incorrectly.

Build: machine-readable truth tables for DET-001, DET-002, and DET-003 covering positives, negatives, empty values, null versus absent, duplicates, mixed identifier formats, and required output fields. Add exact threshold/window boundary cases to DET-002. Add ordering, repeated steps, clock skew, event-time versus ingestion-time, late arrival, and out-of-order cases to DET-003. Define test layers and acceptance thresholds.

Prove: each requirement maps to at least one test; intentionally broken logic produces a useful failure; tests identify both overmatching and undermatching.

## Exercises and answer criteria

1. Write a case that kills an exclusion based only on the maintenance principal. Explain why another unrelated user is a weaker test of that defect.
2. Add a metamorphic check that shuffles the ordered-sequence input. Identify a transformation that should change the result and explain why it is not a valid invariance test.
3. Design an output-contract mutation that preserves result count but corrupts evidence identity. Specify the exact comparison that should fail and the consumer consequence if it survives.

The answer derives expected outcomes from the behavior requirement before editing the implementation and covers a discriminating negative boundary.
