# Chapter 13: The CI Gate for Detection Content

This is a cumulative study checkpoint in the edition, not a separate historical release.

## Artifact and proof scope

Case: a syntactically valid pull request ships without evidence, parity, security, or required metadata.

Build: provider-neutral local validation entry point plus one complete GitHub Actions reference workflow for schema/YAML linting, Sigma validation/conversion, target static checks, unit/regression/mutation subsets, optional replay, parity checks, performance budgets, secret/license/dependency scanning, evidence bundle, immutable artifact creation, and required review. Pin all dependencies. Pin third-party actions by verified full commit SHA with a readable tag comment.

Prove: clean and intentionally failing PRs; fork/untrusted-input behavior; minimal GITHUB_TOKEN permissions; no secrets exposed; protected workflow paths; reproducible artifacts. Never execute untrusted code with privileged pull_request_target or workflow_run patterns.

## Exercises and answer criteria

1. Introduce a query-resource mismatch in a disposable branch and confirm that the local structural check rejects it. Explain why a YAML syntax check would not catch the semantic mismatch.
2. Review the workflow's action hashes, token permissions, checkout configuration, and dependency lock. Identify the evidence needed to verify effective branch protection outside the repository files.
3. Design a trusted release job that consumes an immutable artifact from an approved revision. Specify provenance checks, allowed overlay fields, OIDC trust constraints, environment authorization, and readback evidence without embedding credentials.

The answer keeps untrusted code read-only, pins dependencies, separates deployment authority, and records blocked native gates honestly.
