# Chapter 14: Tune Without Creating Blind Spots

This is a cumulative study checkpoint in the edition, not a separate historical release.

## Artifact and proof scope

Case: analysts suppress an alert flood with a broad, permanent exclusion that also removes the supplied positive case.

Build: evidence-based tuning analysis; population/cohort report; threshold options; before/after results; distinction among deduplication, throttling, suppression, allowlist, exception, and logic change; scoped exception-as-code with reason, owner, approver, expiry, review date, and tests; estimated alert-load effect.

Prove: known positive cases remain; benign load changes are measured; expired and overbroad exceptions fail policy; rollback is available. Never equate lower volume with better detection.

## Exercises and answer criteria

1. Compare the exact maintenance exception with a principal-only filter using the mutation suite. Identify the positive cases the broad filter loses.
2. Propose a consumer-idempotency fix for repeated delivery of the same signal key. Explain why the predicate and accepted behavior can remain unchanged and which delivery tests are required.
3. Prepare a threshold-change proposal for DET-002. Include the changed contract, exact-boundary expectations, representative-load evidence you would need, consumer consequences, and rollback criteria.

The answer distinguishes delivery duplication from benign-match tuning, uses a conjunctive scoped exception, preserves positives, and enforces expiry.

## Reproducible edition experiment

```sh

```

The authored cohort contains 100 unique observations and 20 repeated deliveries. The exact maintenance exclusion retains 60 expected positives; a principal-only exclusion loses 30 of them. This is synthetic contract evidence, not a production precision estimate.
