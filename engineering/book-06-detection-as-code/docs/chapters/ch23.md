# Chapter 23: Own, Review, Migrate, Retire

This is a cumulative study checkpoint in the edition, not a separate historical release.

## Artifact and proof scope

Case: an author leaves, the schema migrates, and an obsolete rule continues consuming resources without a consumer.

Build: catalog record; primary/backup ownership; service objectives; dependency inventory; review cadence; exception-expiry workflow; schema/platform migration plan; consumer-impact check; deprecation notice; replacement/tombstone redirect; archive evidence; retirement approval and rollback window.

Prove: owner-loss and schema-migration tabletop; expired review fails policy; retired content can be traced but is not silently re-enabled. A detection is not complete unless its end of life is controlled.

## Exercises and answer criteria

1. Conduct an owner-loss tabletop using only repository records. List every missing decision or access dependency the backup encounters.
2. Map a principal-field migration that changes both type and case policy. Identify tests needed before native-query comparison.
3. Create a tombstone for a retired DET-003 variant and verify that ordinary reconciliation would not silently enable it again.

The answer preserves current ownership, migration semantics, consumer impact, archive identity, and a tombstone preventing silent reactivation.
